### B3. Usage limits and reset (applies to C too)
- Paid plans: a session limit that resets every 5 hours (window starts at first message and resets in full 5 hours later) plus weekly limits that reset once a week at a fixed time tied to the account; some plans have a separate weekly limit for Fable [https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work]
- Free: limits reset every 5 hours [https://support.claude.com/en/articles/10684626-enabling-and-using-web-search]
- Weekly limits apply across all models; claude.ai, Claude Code and Claude Desktop share the same limit; check Settings > Usage [https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work]
- What consumes usage: message length, attachment size, conversation length, tools (Research, web search), model choice, effort level, artifact creation, multi-step tasks (code, files, browsing) [https://support.claude.com/en/articles/9797557-usage-limit-best-practices]
- Project content is cached and counts less when reused; cache expires after inactivity, so first message after a long break counts it in full [https://support.claude.com/en/articles/9797557-usage-limit-best-practices]
- At a limit: wait for reset, upgrade (applies immediately), or use usage credits (paid plans). Usage-based Enterprise has no set limits [https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work]
- Conserve: use projects, short instructions, remove unused files, lower effort or turn thinking off, turn off connectors and web search when unneeded (tools and connectors are token-intensive) [https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work]
- Tips: plan first, be specific, reuse context, batch requests, match task [https://support.claude.com/en/articles/9797557-usage-limit-best-practices]

## C. Feature details

### C1. Projects
- Definition: self-contained workspaces with their own chat histories and knowledge bases [https://support.claude.com/en/articles/9517075-what-are-projects-and-how-do-i-use-them]
- Project knowledge: uploaded documents, text files, code snippets available to every chat in that project. Claude does not share context between chats unless it is in the knowledge base [https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects]
- Project instructions: set via "Set project instructions"; apply to all chats in the project; used for tone, role, industry perspective, workflow guidelines [https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects] [https://support.claude.com/en/articles/10185728-understanding-claude-s-personalization-features]
- Project name and description are not visible to Claude [https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects]
- Scope ladder: "Instructions for Claude" (formerly profile preferences) = all conversations; project instructions = chats in one project; Skills = activated on demand [https://support.claude.com/en/articles/10185728-understanding-claude-s-personalization-features]
- Large knowledge: when knowledge "approaches the context window limit", Claude automatically turns on RAG; capacity up to 10x; no manual toggle; can switch back to in-context if knowledge shrinks; a visual indicator shows RAG is active and Claude uses a "project knowledge search" tool [https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects]
- RAG threshold: no exact number in the official article ("approaches the context window limit"). A claimed ~2% figure is a Reddit/GitHub rumor: **UNCONFIRMED, do not teach** [https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects]
- RAG plans: Pro, Max, Ultra, Team, Enterprise (an older March 2026 version reportedly said all plans; current says paid) [https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects]
- RAG works with web search, extended thinking, and Research. Practice: upload everything upfront, clear filenames, group related files, name documents in questions [https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects]
- Visibility: Private (only invited members) or Public/organization (everyone in org can view and use; shows on "Organization" tab; chats stay private unless shared). Creator can switch anytime via Share [https://support.claude.com/en/articles/9519189-project-visibility-and-sharing]
- Permission levels (Team/Enterprise): **Can view** = see contents, knowledge, instructions and chat, not edit. **Can edit** = change instructions and knowledge, manage members, contribute. No separate "Owner" level is defined in the article [https://support.claude.com/en/articles/9519189-project-visibility-and-sharing]
- Sharing a project does not share its chats; chats are shared individually [https://support.claude.com/en/articles/9519189-project-visibility-and-sharing]
- Admins (Owners) can turn sharing off org-wide, or on Enterprise for specific roles; existing shares remain, public projects become private [https://support.claude.com/en/articles/9519189-project-visibility-and-sharing]
- Projects page tabs: Your projects, Organization, Shared with you [https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects]
- Project memory: each project has its own memory; project chats use project memory plus account (non-project) memory, never other projects' memory; "Use account memory" off = full isolation [https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects]
- Archive keeps sharing, members, permissions and knowledge; archived projects cannot be deleted until unarchived; star projects for quick access [https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects]
- Incognito is not available inside projects (no ghost icon); alternative is turning Memory off in "+" menu before first message [https://support.claude.com/en/articles/12260368-use-incognito-chats]
- Beta "new projects" version (one conversation, parallel cloud threads, Library) limited to select Pro/Max/Ultra users. Not exam scope. [https://support.claude.com/en/articles/9517075-what-are-projects-and-how-do-i-use-them]
- Team/Enterprise: connectors are only available in private projects; chats with synced content cannot be shared [https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities]

### C2. Artifacts
- Definition: content Claude makes (document, deck, design, dashboard, small interactive tool) that opens beside the chat and can be edited, revisited, shared [https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them]
- When Claude creates one: content is substantial (typically over 15 lines), self-contained, and likely to be reused. Otherwise it answers inline [https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them]
- Types listed: documents, code snippets, single-page websites, images, diagrams/flowcharts, dashboards, small interactive tools [same URL]
- Templates: Docs, Slides, Design (all plans); Dashboards beta (Pro+); Motion beta (Team/Enterprise, exports MP4) [same URL]
- Editing: ask in chat; edit template artifacts directly; highlight text and "Edit with Claude"; editing an earlier chat message creates a separate chat version; "Try fixing with Claude" for errors (not guaranteed) [same URL]
- Sharing: artifacts start private; sharing settings control who opens them; sharing settings changed on web or Desktop, not mobile [same URL]
- Export: Docs to Word/PDF/Markdown/Google Docs; Slides to PowerPoint/PDF/Google Slides; Design to zip/PDF/PowerPoint/HTML [same URL]
- Legacy artifacts (made before 16 Sep 2026) can still be published/shared but new ones cannot be created [same URL]
- AI-powered artifacts ("Artifacts that use Claude"): artifacts can call Claude; viewers sign in with their own Claude account; no API key; creator pays nothing; usage counts against each viewer's plan; setting in Settings > Capabilities [same URL]
- Artifacts with connected apps (Pro+, web/desktop): need first-time approval; tools requiring per-action approval are not available; each user connects own apps [same URL]
- Stored data: personal or shared storage, 20 MB per artifact, text only [same URL]

## F. AI Fluency framework (4D)

Source of truth: Anthropic AI Fluency Key Terminology Cheat Sheet and Framework one-pager (Dakan, Feller, Anthropic, CC BY-NC-SA 4.0, (c) 2025) [https://www-cdn.anthropic.com/4396730ed190e691a3712cf2fd6bfe35509deca2.pdf] [https://www-cdn.anthropic.com/b383cf6baddbfc72fdf8b0ed533a518e2872d531.pdf]. Framework site: https://aifluencyframework.org/

- AI Fluency: working with AI systems in ways that are effective, efficient, ethical and safe [framework one-pager PDF above]
- The 4Ds are interconnected collections of skills, knowledge, insights and values [framework one-pager PDF above]
- **Delegation** (one-pager): "Setting goals and deciding whether, when and how to engage with AI." Cheat sheet: deciding what work should be done by humans, what by AI, and how to distribute tasks between them; includes understanding goals, AI capabilities, and strategic choices about collaboration
  - Problem Awareness: clearly understanding your goals and the nature of the work before involving AI
  - Platform Awareness: understanding capabilities and limitations of different AI systems
  - Task Delegation: thoughtfully distributing work between humans and AI to leverage the strengths of each
- **Description** (one-pager): "Effectively describing goals to prompt useful AI behaviors and outputs." Cheat sheet: clearly defining outputs, guiding AI processes, specifying desired AI behaviors and interactions
  - Product Description: defining what you want in terms of outputs, format, audience, and style
  - Process Description: defining how the AI approaches your request, e.g. step-by-step instructions
  - Performance Description: defining the AI's behavior during collaboration, e.g. concise or detailed, challenging or supportive
- **Discernment** (one-pager): "Accurately assessing the usefulness of AI outputs and behaviors." Cheat sheet: thoughtfully and critically evaluating outputs, processes, behaviors and interactions; assessing quality, accuracy, appropriateness; determining areas for improvement
  - Product Discernment: evaluating the quality of what AI produces (accuracy, appropriateness, coherence, relevance)
  - Process Discernment: evaluating how the AI arrived at its output, looking for logical errors, lapses in attention, inappropriate reasoning steps
  - Performance Discernment: evaluating how the AI behaves during your interaction, whether its communication style is effective for your needs
- **Diligence** (one-pager): "Taking responsibility for what we do with AI and how we do it." Cheat sheet: using AI responsibly and ethically; thoughtful choices about systems; transparency; accountability for AI-assisted work
  - Creation Diligence: being thoughtful about which AI systems you use and how you interact with them
  - Transparency Diligence: being honest about AI's role in your work with everyone who needs to know
  - Deployment Diligence: taking responsibility for verifying and vouching for the outputs you use or share
- Three modes of AI interaction (one-pager and cheat sheet):
  - **Automation**: AI performs specific tasks based on specific human instructions; human defines what, AI executes
  - **Augmentation**: humans and AI collaborate as thinking partners; iterative back-and-forth, both contribute
  - **Agency**: humans configure AI to work independently on their behalf (including interacting with other humans or AI); human sets the AI's knowledge and behavior patterns rather than exact actions
- Loops: the Academy course teaches a "Description-Discernment loop" explicitly [https://anthropic.skilljar.com/ai-fluency-framework-foundations]. A "Delegation-Diligence" loop appears only in a Coursera listing: **UNCONFIRMED as official** [https://www.coursera.org/learn/ai-fluency-framework-foundations]
- Platform/Problem Awareness and Task Delegation labels: confirmed on the official cheat sheet (an earlier search result called them unconfirmed; the PDF settles it).
- Academy course structure and lesson titles (Delegation, A closer look at Delegation, Project planning and Delegation, Description, A closer look at Description, Discernment, ..., Diligence) [https://anthropic.skilljar.com/ai-fluency-framework-foundations]. Lesson text is behind login; definitions above come from the PDFs.
- Related terms from the cheat sheet useful in D1/D2: hallucination (confidently states something plausible but incorrect); context window; RAG (connects model to external knowledge to improve accuracy and reduce hallucination); bias; chain-of-thought; few-shot; role definition; output constraints; think-first approach [https://www-cdn.anthropic.com/4396730ed190e691a3712cf2fd6bfe35509deca2.pdf]
- Exam link: Course 4 builds on Description; Course 5 on Discernment; Course 7 anchored on Delegation; Course 8 on Diligence-type judgment (inference) [A4 sources]

## G. Prompting guidance for app users

Primary: Help Center "Introduction to prompt design" is very short: Claude is conversational; treat it like a new contractor with no context on you, task or organization; be very specific; deeper guidance is in API docs [https://support.claude.com/en/articles/7996853-introduction-to-prompt-design] (summary from fetch; German version has the "contractor" wording). Main technique source: API docs best practices, current for Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5 [https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices]

- Be clear and direct; specify output format and constraints; use numbered steps when order matters; "key test": show the prompt to a colleague with minimal context, if they would be confused Claude will be too [best-practices URL]
- "Brilliant but new employee who lacks context on your norms and workflows" analogy [best-practices URL]
- Give context or motivation (the reason): example "read aloud by text-to-speech, so never use ellipses"; Claude can generalize from the explanation [best-practices URL]
- Examples (few-shot/multishot): relevant, diverse, structured in `<example>` tags; 3-5 examples for best results [best-practices URL]
- XML tags separate instructions, context, input, examples (`<instructions>`, `<context>`, `<input>`); consistent descriptive names; nest when hierarchical [best-practices URL]
- Role: one sentence in the system prompt focuses behavior and tone [best-practices URL]
- Long documents (20k+ tokens): put long-form data at the top above the query; queries at the end can improve quality by up to 30% in tests; wrap multiple docs in `<document>` tags with source metadata [best-practices URL]
- Ground in quotes: for long documents ask Claude to quote the relevant parts first, then do the task [best-practices URL] [https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations]
- Let Claude say "I don't know": explicitly give permission to admit uncertainty; "can drastically reduce false information" [https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations]
- Verify with citations: have Claude cite quote for each claim; if no supporting quote, retract the claim [reduce-hallucinations URL]
- Other verification: best-of-N (rerun and compare; inconsistency signals hallucination), iterative refinement, restrict to provided documents, review summarized thinking [reduce-hallucinations URL]. Techniques reduce but do not eliminate hallucination; always validate high-stakes info [same URL]
- Step-by-step/thinking: current docs say general instructions ("think thoroughly") often beat hand-written step-by-step plans; models use adaptive thinking [best-practices URL]. Cheat sheet still defines chain-of-thought and think-first approach as concepts [https://www-cdn.anthropic.com/4396730ed190e691a3712cf2fd6bfe35509deca2.pdf]
- Prompt chaining: break a task into sequential steps and inspect intermediate outputs; common pattern = draft, review against criteria, refine [best-practices URL]. In chat this means separate turns.
- Exam style link: Course 4 five-ish component structure (audience, specific points, format, length) [https://anthropic-partners.skilljar.com/path/claude-associate/prompting-task-execution]. The exact named components (e.g. brief, reason, source, example per certsafari) are **UNCONFIRMED from an official page** (page truncated).
- Iteration: diagnose, change one thing, test (certsafari wording; official Course 4 says "refine diagnostically") [Course 4 URL]
- Usage tie-in: clear specific prompts and batching reduce follow-ups and usage [https://support.claude.com/en/articles/9797557-usage-limit-best-practices]
